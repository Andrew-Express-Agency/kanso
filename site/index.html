Questions

Price, what stays on the machine, and how this differs from a click-test runner.

01

Does it cost anything?

The repository is MIT. There is no account and no paid tier here. Clone it, run npm install and npm run build, then node bin/kanso.js. The package named kanso on npm is a different CouchApp tool.

02

Does Kanso send my code or diffs to any external server?

The CLI does not upload the diff, the screenshots, or memory.json. A run writes .kanso/vibe-reports/vibe-report.md, mobile_393.png, and desktop_1440.png. Those files leave only if you git push them.

03

How does kanso vibe differ from Playwright or Cypress?

Playwright and Cypress click through flows and assert on them. kanso vibe does not. It opens Chrome at 393×852 and 1440×900, flags overflow, gaps over 85px, text under 2:1, and tap targets under 36px, and exits 1 in CI when the score is under the threshold. The default threshold is 80.

04

Which AI models and coding agents are supported?

kanso handoff writes .kanso/handoff.patch from the working tree. kanso handoff apply restores that patch. Any tool that can apply a git diff can pick up the work.

05

Can I use Kanso in GitHub Actions or CI/CD?

Run kanso vibe http://localhost:3000 --ci --threshold 90. The default gate is 80. Under the number you set, the process exits 1, which fails the job if the workflow treats that as a failure.
