Frequently Asked Questions

Everything you need to know about Kanso's sovereign architecture, privacy model, and licensing.

01

Is Kanso really 100% free and open-source?

Yes. Kanso is released under the permissive MIT License. There are no trial periods, no hidden credits, no cloud subscription tiers, and no locked features. We believe foundational developer sovereignty belongs to everyone.

02

Does Kanso send my code or diffs to any external server?

Never. Kanso contains zero telemetry, zero analytics trackers, and zero cloud uploads. Your code, uncommitted diffs, screenshots, and memories never leave your machine unless you explicitly commit and push them with Git.

03

How does kanso vibe differ from Playwright or Cypress?

Playwright and Cypress are behavioral test runners for assertions and user flows. Kanso is a visual regression check: it opens local Chrome at 393×852 and 1440×900, checks mobile horizontal overflows, empty layout voids over 85px, and contrast failures under 4.5:1, and exits non-zero if the layout breaks.

04

Which AI models and coding agents are supported?

Every model. Because Kanso writes a standard Git diff patch (.kanso/handoff.patch), any model or tool (Claude Code, Cursor, Codex, Gemini, Grok, Aider) can apply the patch directly and continue work without losing uncommitted progress.

05

Can I use Kanso in GitHub Actions or CI/CD?

Yes. Run kanso vibe http://localhost:3000 --ci --threshold 90 in your pipeline. If the score drops below the threshold, Kanso exits with code 1 and blocks the PR.
