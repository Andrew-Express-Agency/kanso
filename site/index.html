Frequently Asked Questions

Everything you need to know about Kanso's sovereign architecture, privacy model, and licensing.

01

Is Kanso really 100% free and open-source?

Yes. Kanso is released under the permissive MIT License. There are no trial periods, no hidden credits, no cloud subscription tiers, and no locked features. We believe foundational developer sovereignty belongs to everyone.

02

Does Kanso send my code or diffs to any external server?

Never. Kanso contains zero telemetry, zero analytics trackers, and zero cloud uploads. Your code, uncommitted diffs, screenshots, and memories never leave your machine unless you explicitly commit and push them with Git.

03

How does VibeTest differ from Playwright or Cypress?

Playwright and Cypress are behavioral assertion frameworks designed for unit and E2E flows (e.g. "does clicking this button route to /checkout"). VibeTest is an aesthetic and visual intelligence radar built specifically for AI-generated codebases. It monitors layout integrity, catches horizontal mobile overflows, identifies accidental whitespace voids (>85px), and verifies WCAG contrast ratios across both desktop and mobile viewports automatically.

04

Which AI models and coding agents are supported?

Every single one. Because Kanso relies on universal Git diff patches and clean Markdown trajectory handoffs, it works seamlessly with Claude Code, Cursor, Codex, Gemini CLI, Grok, Windsurf, Aider, Ollama, and local models. When switching agents, the next assistant resumes work with 100% precision.

05

Can I use Kanso in GitHub Actions or CI/CD?

Yes! Simply add kanso vibe http://localhost:3000 --ci --threshold 90 to your test pipeline. If any PR causes a visual regression or drops the VibeScore below 90, Kanso exits with code 1, preventing defective code from reaching production.
